# Selected-runtime retirement beside a live cron

The [selected dual-cron receipt](evidence/m11c-selected-runtime-retirement-dual.json)
qualifies retirement beside another simultaneously live cron on the frozen local
Linux arm64 Docker candidate. The complete M11c acceptance audit remains open.
Public candidate enrollment and ordinary cron admission stay closed.

This profile complements the [sequential retirement chain](cron-selected-retirement.md).
Each retirement uses a fresh installation. Earlier installations remain stopped,
and every volume is retained.
The runtime catalog supplies the same immutable product and storage images used by
the other selected-runtime profiles. No image or native build is required.

## Source schedules and retained history

A healthy minute cron runs beside an imports queue with real, unattempted input.
A stopped snapshot confirms dispatch pause before its selected future deadline.
Retiring the queue preserves its input and artifact while moving its fleet to a
new namespace and node identities. The surviving cron stays held before controller
startup and after recovery acknowledgment. Separate resume completes future jobs.

An ordinary scoped upload creates a second minute cron in the freed fleet. Its
ledger tables and wakes start empty, with the declared seed configuration. It has
a separate required-secret value and revision. Approval refuses the first cron's
revision after the second cron's configuration exists, then pins the exact selected
revision. The retired queue's credential and name cannot authorize a new deployment,
credential or approval. Failed operations preserve controller and private files.

Both crons run autonomous successful jobs, with a shared successful minute and a
common upcoming alarm. Backup must confirm pause for both before that same selected
deadline. There is one backup attempt; a missed deadline refuses the trial.
The snapshot preserves the earlier queue retirement history.

## Retirement and survivor recovery

Retiring the original cron changes only its fleet's namespace and node identities,
plus the new installation's networks. The other cron's policy remains intact.
Restored native processes start before controller and ingress. The survivor stays
held for at least 62 seconds before controller startup. This cold observation
ends after the common deadline; in the recorded run, that deadline is already
overdue when the interval starts. The survivor remains held for another interval
after explicit acknowledgment. Recovery acknowledgment restores
HTTP access and leaves scheduled dispatch paused.

The original cron's scoped credential, name, approval and dispatch resume are
refused. A separate resume of the survivor completes future native jobs. A quiet
observation lasts at least 125 seconds. Independent acceptance requires complete
attempt, occurrence and result records for two distinct future minutes per job,
including work at least a minute into that window. Old ledger rows remain unchanged,
and no wake points at a time before resume. This does not promise delivery of
minutes skipped while paused or execution exactly once for external effects.

The retired fleet stays unassigned after survivor resume. Both retired prefixes,
artifacts, private configuration and earlier queue input remain intact. Separate
source audit restores hold both original crons and also the initial cron/queue
installation before controller startup and after acknowledgment. Both source
snapshots still match every archived source-volume entry after all restores.
Independent runtime policies are checked separately.

## Independent acceptance

The receipt identifies the actual terminal exit, archived sources and private
independent auditor by hash. A printed pass is insufficient. The auditor verifies
raw native signatures with OpenSSL and refuses altered signatures, rebuilds key
maps against the exact policies, reads retained controller and policy volumes,
hashes approved artifacts and checks separate secret ownership and revision pins.
Node identity is signed; the host is a recorded policy label. Public timing and
count summaries derive from the scanned raw receipt and independent audit records.
The receipt identifies the retained summary writer and publication scanner by
hash.

Source inventory includes tracked and unignored repository scripts. A separate parser follows the
driver's static local imports without executing them and requires each dependency
in the archived inventory. The auditor also checks all shipped program files and
native executable hashes against the immutable image, all snapshot file hashes,
complete source-volume entries and exact restored retired-prefix subtrees.
Canonical Compose hashes can differ after backup while parsed configuration
remains equal; the audit checks that equality separately from each byte hash.
The import walk starts at the driver and CLI. Dynamic imports, `require()` and
code generated for subprocesses remain outside that walk. The inventory hashes
local scripts and packages, plus the lockfile; it does not attest installed
`node_modules` contents. Immutable image contents have their separate check.

The earlier sequential receipt records 485 source files and omits two imported
helpers: `scripts/queue-probe/prefix-fingerprints.mjs` and
`scripts/guestbook-browser.mjs`. Its independent
archive-to-volume comparisons remain recorded separately. The dual profile's
expanded inventory and import check cover both helpers. Neither historical
fingerprint is an archived executed file.

Final acceptance requires no owned containers or networks, all 40 volumes still
present, unchanged retired bytes and successful privacy scans of public surfaces,
decoded artifacts, diagnostics and the final receipt bytes. The published receipt
records measured durations and exact audit counts.

The run takes 1,206.517 seconds. Independent acceptance verifies 624 recorded
source files, 135 static local imports, 42 signatures and 42 altered-signature
refusals. Five controller volumes and all 40 volumes remain. The audit compares
590 complete source-volume entries and four restored retired-prefix subtrees.
All 970 tests, syntax checks and the quality gate pass. Ten weakened validators
and seven independent-audit guard mutations are rejected.

## Run and retain

Use the commit introducing the receipt, with its pinned images, dependencies and
checked native source tree already cached. Keep unrelated installations intact.
The output directory must be new and private:

```sh
node scripts/cron-probe/selected/retirement-dual.mjs .fogd/selected-retirement-dual
```

Keep terminal metadata, logs, snapshots, the archived sources, independent auditors
and post-write receipt hashes with the private evidence. Failed and interrupted
trials retain separate evidence and volumes and do not qualify this profile.
Temporary reviews and handoff documents stay outside tracked files.

Per-worker CPU quotas and CPU-exhaustion behavior remain unqualified. This profile
does not qualify remote or three-fleet scheduled recovery, Workflows, general
Durable Object alarms, general drain, lifecycle or rebalance fencing, arbitrary
untrusted tenants, or hosted Cloudflare execution.
