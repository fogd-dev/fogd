**Verdict: no blockers.** The implementation matches the spec and the accepted amendments on every axis I was asked to check. Three low-priority items follow, none of which invalidates the stated contract.

**Confirmed against code**

- **Credential confidentiality.** Values enter only via `PUT /v1/apps/:app/secrets` behind admin Basic auth plus CSRF/origin, with a 64 KiB cap and fixed parse errors (`admin-secrets.mjs`, `http.mjs:9-19`). Every error string on the secrets path is fixed text; none echoes a name or value. Revision files and `index.json` are written 0o600 in a 0o700 directory via `saveJson`. State, `/v1/admin`, the HTML page, `fogd admin list`, and `deploymentStatus` carry only names and opaque revision IDs. The platform test asserts both the HTTP response and state exclude the submitted value, and the smoke test asserts the same for the artifact manifest.
- **Pinning, rotation, failure.** `Secrets.select` runs before `backend.claim`, requires the explicit revision to equal the pinned one or the current one, and verifies every declared name is present in the stored file (`secrets.mjs:29-39`). `request.secretRevision` is set before the first persisted step, so controller interruption keeps the pin. `replaceSecrets` only writes a new revision and never touches running code. Retry after rotation is refused with the "pinned" error, and the restarted-controller test proves the pinned value is what gets materialized.
- **Fail-closed redaction.** `app.privateConfiguration ||= Boolean(selected.revision)` is persisted and consulted in both the activation catch and `reconcile`, so later non-secret releases of a once-private app still get fixed diagnostics. The `validating-application` step maps to a fixed submitter message.
- **Artifact boundary.** `materialize` copies to `dir/execution/<id>` with `errorOnExist`, rewrites only the copy's `wrangler.json` at 0o600, and the `finally` plus `Secrets.init` remove it. The admin manifest endpoint reads `dir/artifacts/<id>`, never the execution copy. `fogd-deployment.json` is digest-covered, allowlisted on receipt, and validated against the canonical config; a `secrets` key left in a submitted `wrangler.json` fails the canonical-equality check.
- **Native auth.** Upstream `/__void/ready` runs `validateEnv` first and returns `{ready:true}` before `internalRoute`, so it needs no token and reports boot-time schema failures as non-200. It is reachable only inside the fleet networks; the gateway 404s `/__void` paths and strips `x-void-*`. `secretNames` rejects `__` prefixes, so `__VOID_PROXY_TOKEN` cannot be smuggled in as a secret. Better Auth uses the per-request origin as `baseURL`, so cookies are host-scoped per app.
- **Password adapter.** Parameters, NFKC, hex salt, `salt:key` format, fixed-length `timingSafeEqual` on a regex-validated hash, and memory within the 64 MB cap. The test cross-checks against Node scrypt in both directions.

**Low-priority items**

1. **CSRF comparison regressed to a plain `!==`** in `admin-secrets.mjs:2`. The previous inline check used the hashed `timingSafeEqual` helper. Practical risk is negligible here since the token is only a same-origin guard behind Basic auth, but it is a one-line restore: export `equal` from `http.mjs` or move it into `admin-secrets.mjs` and use it.
2. **Retry button silently reuses the pinned revision.** The HTML "Retry approval" button pre-fills `d.secretRevision`, and the revision is only visible inside the collapsed details block. This is the "stale secrets on retry" trap the earlier review flagged. Putting the short revision ID in the button label or the article header is enough.
3. **`applicationReady` has no retry.** It makes a single 10 s request per node right after the celld health check. A slow cold cell start would fail activation with a fixed diagnostic and force an admin retry. Not a correctness issue, just a flake surface; a short retry loop like `ready` uses would remove it.

Nothing else found. Skipped: broader future-scope advice (encryption at rest, revision GC, logging of raw errors) since the contract explicitly defers it.
