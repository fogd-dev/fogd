### Prioritized Findings

#### 1. [High — Security / Asset Privacy & Reproducibility] `stageArtifact` copies `dist/ssr` unfiltered into `worker/`, leaking `@cloudflare/vite-plugin`-emitted `.dev.vars` and host-local paths
* **Files:** [`packages/runtime/src/artifact.mjs`](file:///Users/sgtpooki/code/sgtpooki/fogd/packages/runtime/src/artifact.mjs#L121-L126), [`packages/runtime/src/assets.mjs`](file:///Users/sgtpooki/code/sgtpooki/fogd/packages/runtime/src/assets.mjs#L7-L18)
* **Issue:**
  1. **Unfiltered `worker/` copy (`artifact.mjs:122`):** During `vite build`, `@cloudflare/vite-plugin`'s `outputConfigPlugin` runs for both `client` (`dist/client`) and `void_worker` (`dist/ssr`). In `void_worker`, if a project has a `.dev.vars` or `.env` file, `getLocalDevVarsForPreview` (`wrangler.unstable_getVarsForDev`) serializes those local secrets into `dist/ssr/.dev.vars` for `vite preview`. It also writes `dist/ssr/wrangler.json` containing the developer's local absolute filesystem paths (`configPath` / `userConfigPath`). Because [`stageArtifact`](file:///Users/sgtpooki/code/sgtpooki/fogd/packages/runtime/src/artifact.mjs#L122) runs `await cp(bundleDir, join(outputDir, 'worker'), { recursive: true })` without filtering, any `dist/ssr/.dev.vars` is copied into `outputDir/worker/.dev.vars` and uploaded to the controller in [`manifest()`](file:///Users/sgtpooki/code/sgtpooki/fogd/packages/runtime/src/manifest.mjs#L8-L14). In addition, `outputDir/worker/wrangler.json` (plus `index.js.map`, `.vite/manifest.json`, and extracted `assets/*.css`) is hashed into `artifactDigest`, embedding host paths (observable in `.fogd/releases/guestbook/*/worker/wrangler.json`) and making digests non-reproducible across different checkout paths. By contrast, upstream Void's `copyBundle` ([`.upstream/void/packages/void/src/cli/cf-build-output.ts`](file:///Users/sgtpooki/code/sgtpooki/fogd/.upstream/void/packages/void/src/cli/cf-build-output.ts#L76-L86)) explicitly strips `wrangler.json`, `.dev.vars`, `.vite/manifest.json`, `*.css`, and `*.css.map` from `dist/ssr`, and `celld deploy` with `no_bundle: true` ([`.upstream/celld/crates/celld/deploy.rs`](file:///Users/sgtpooki/code/sgtpooki/fogd/.upstream/celld/crates/celld/deploy.rs#L630-L645)) only reads `config.main` and sibling `.wasm` files.
  2. **Default exclusions and negation ordering in [`stageAssets`](file:///Users/sgtpooki/code/sgtpooki/fogd/packages/runtime/src/assets.mjs#L8-L13):**
     * Line 8 only adds `['.DS_Store', '.env', '.env.*']` as defaults, omitting `'.dev.vars'` and `'.dev.vars.*'` (which upstream Void includes by default in [`.upstream/void/packages/void/src/cli/cf-version-api.ts`](file:///Users/sgtpooki/code/sgtpooki/fogd/.upstream/void/packages/void/src/cli/cf-version-api.ts#L915-L924)). Currently `.dev.vars` is only ignored if `.assetsignore` lists it, and `.dev.vars.*` (e.g., `.dev.vars.local`) is not excluded by default.
     * Because `.assetsignore` is added *after* the defaults on the same `ignore()` instance (`line 9`), a broad negation rule in `.assetsignore` (such as `!*` or `!.*`) un-ignores `.env` / `.env.*`. Conversely, an allowlist-style `.assetsignore` (`*\n!assets/**`) causes `ignored.ignores(path)` (`line 13`) to drop root `_headers` and `_redirects` despite the comment on lines 5–6.
* **Fix:** Exclude non-runtime files (`wrangler.json`, `.dev.vars`, `.dev.vars.*`, `.env`, `.env.*`, `.vite/manifest.json`, `*.css`, `*.map`) when staging `outputDir/worker`. In `stageAssets`, enforce default secret/OS exclusions (`.DS_Store`, `.env`, `.env.*`, `.dev.vars`, `.dev.vars.*`) independently of `.assetsignore` negations, and explicitly preserve root `_headers` and `_redirects` when not explicitly named.

#### 2. [Medium — Test Correctness & Flakiness] Post-reload hydration race and weakened `/history` check in browser/fullstack smoke tests
* **Files:** [`scripts/guestbook-browser.mjs`](file:///Users/sgtpooki/code/sgtpooki/fogd/scripts/guestbook-browser.mjs#L21-L31), [`scripts/fullstack-smoke.mjs`](file:///Users/sgtpooki/code/sgtpooki/fogd/scripts/fullstack-smoke.mjs#L75-L80)
* **Issue:**
  1. **Post-reload hydration race ([`guestbook-browser.mjs:28-31`](file:///Users/sgtpooki/code/sgtpooki/fogd/scripts/guestbook-browser.mjs#L28-L31)):** On initial load (`lines 21-24`), clicking `Check saved messages` is wrapped in `await expect(async () => { ... }).toPass({ timeout: 30000 })` because SSR HTML is interactive-looking before React hydration attaches `onClick`. After `await page.reload()` (`line 28`), `toContainText(text)` resolves immediately on SSR HTML, and `line 30` clicks `Check saved messages` once without `toPass`. If hydration after reload finishes after `line 30`, the click is dropped and `line 31` times out.
  2. **Weakened `/history` SSR assertion ([`fullstack-smoke.mjs:77`](file:///Users/sgtpooki/code/sgtpooki/fogd/scripts/fullstack-smoke.mjs#L77)):** React 19 SSR serializes `{m.label}: {m.text}` with comment markers (`visitor<!-- -->: <!-- -->...`). Relaxing the assertion to `/<h1>History<\/h1>/` means `/history` is no longer checked for rendering either the migrated default `visitor` label or `firstMessage`.
  3. **Unchecked CLI status output ([`fullstack-smoke.mjs:79`](file:///Users/sgtpooki/code/sgtpooki/fogd/scripts/fullstack-smoke.mjs#L79)):** `await run(process.execPath, [cli, 'status', second.id], { env })` only verifies exit code `0` without capturing stdout to assert `status === 'active'`, `step === 'complete'`, and `error === null`.
* **Fix:** Wrap the post-reload button click/status check in `toPass`, assert that `/history` output contains both `visitor` and `firstMessage`, and capture + parse the JSON output of `fogd status`.
