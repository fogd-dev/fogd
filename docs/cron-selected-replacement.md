# Selected runtime scheduled replacement

This is a historical qualification profile. For current admission and scope, see
the [M11c acceptance audit](m11c-acceptance.md). Reproduce it with the source
revision identified below.

The [selected replacement receipt](evidence/m11c-selected-runtime-replacement.json)
qualifies compatible updates and original-occurrence retries on the frozen local
Linux arm64 Docker candidate. Three ordinary offline-built Void artifacts pass
scoped HTTPS upload and exact approval. Active-survivor retirement and the complete
M11c acceptance audit remain open. Public candidate enrollment and ordinary cron
admission stay closed.

## Reproduce the profile

Use the commit that introduces this receipt; its recorded base commit alone omits
the new qualifier. Its source inventory identifies the executed files. The cached
runtime, storage and SDK images must match the receipt, with dependencies and the
Playwright browser already available. From the checkout root, run:

```sh
node scripts/cron-probe/selected/replacement-profile.mjs .fogd/selected-replacement-UNIQUE
```

The output directory must be new. The driver creates a private two-fleet
installation with loopback HTTPS, scoped builder credentials and internal candidate
enrollment. The three replacement builds run with networking disabled. The profile
installs no dependencies, builds no images, compiles no native code and calls no
hosted service.
Private inputs, logs, screenshots and executed-source copies stay in ignored
storage. Successful cleanup removes owned containers and networks and retains all
eight named volumes. Require actual terminal exit zero and the final receipt;
a progress line alone does not establish a pass. The recorded run takes 396.3
seconds.

## Compatible migration before publication

The old release records an advisory callback held before its business commit.
Inventory completes normally. A normal exact-artifact approval pauses dispatch and
applies the compatible SQL migration. The old callback keeps recording progress
while the controller is held immediately before publication.

A fixed private control releases that original callback only after checking the
expected installed policy, both signed native identities, the old active approval,
its artifact and native version, and the new pinned approval and secret revision.
The atomic release also checks the selected occurrence and pending attempt. The
old callback then completes on the changed schema before publication and before
the native 15-second operation deadline. The proof combines a missing business row
after observed migration with its later recorded commit; the added column's default
value alone cannot prove ordering. The inventory result saved before migration
provides a nonempty retention check.

## Interrupted work and native generation release

The middle release holds advisory before commit and inventory after commit. Both
record heartbeats after the final approval's pause and migration checkpoint. The
qualifier measures the owning generation's adoption time and plans publication
against its native maintenance interval. An unsuitable phase is refused before
publication, rather than counted as a runtime failure.

Publication swaps out the old cron generation before the operation deadline. The
last durable application progress must be within 300 milliseconds of the exact
native swap log. Both attempt rows remain unfinished and unchanged past the native
operation deadline and the fixture's 20-second hold deadline. A quiet check precedes
the old generation's measured maintenance tick and actual release. Attempts,
occurrences and business results remain unchanged after that release. Inventory's
saved result survives; advisory has no recorded completion.

This measures D1 progress and native generation release. It does not establish
termination of arbitrary external effects, general drain or automatic replay of
abandoned work. Native pause prevents new callbacks without promising to drain
running callbacks.

## Lost acknowledgment, later work and browser state

The final release uses the ordinary app's lost-reply source mode. Advisory saves a
business result and throws. Before the persisted retry is due, the qualifier
records that wake and its matching current alarm. Both jobs run twice under the
original scheduled time and unchanged owner. Each retains one business row, the
original saved timestamp and one duplicate counter increment. A later healthy
minute succeeds using final-release code.

The ordinary browser shows fresh saved inventory and advisory values and their
stored timestamps. It also identifies the earlier advisory occurrence as unfinished.
The exact occurrence and absence of a completion are checked in the API and visible
page. Source-mode changes do not manually trigger jobs. The screenshot passes
visual inspection, and page errors and unsuccessful responses are refused.

A final confirmed pause crosses a natural minute, the operation deadline and an
observation margin. Attempt, occurrence, result and fixture-control rows remain
unchanged, with native pause confirmed and no current alarm. Wake objects remain
advisory hints; this profile does not require obsolete hints to disappear or remain
unchanged. Earlier rows are compared across both updates, retries and later work.
The separate imports application's stored rows and signed process keys remain
unchanged.

## Independent evidence and limits

Independent acceptance checks executed source hashes, offline artifact digests,
retained controller files, all three approval versions and their shared pinned
secret revision. Fresh native proofs verify against the independent fleet policy;
altered signatures are refused. Cached image inspection verifies the native binary,
supervisor and shipped program hashes. Service exits, privacy scans, the final
receipt's bytes, owned-resource removal and all retained volumes are checked.
The audit verifies 466 executed sources, ten signatures and ten altered-signature
refusals, all three retained artifacts and 63 shipped programs. All 904 standard
tests, syntax and quality checks pass.

In the recorded run, old work completes 1.865 seconds after its scheduled time.
The later swap occurs after 8.282 seconds, the quiet check after 23.648 seconds and
the owner generation release after 32.379 seconds. The persisted lost-reply retry
is observed 3.630 seconds before its deadline. These are measured profile margins.

The profile uses the checked native timing defaults. It qualifies no per-worker CPU
quota or CPU-exhaustion behavior. The ledger cannot record invocations that fail
before their first durable write. Remote operation, Kubernetes scheduled lifecycle,
Workflows, arbitrary Durable Object alarms and exactly once external effects remain
outside this receipt.
